# مهراد AI — استودیوی فارسی لوگو

نسخهٔ آزمایشی بر پایهٔ فایل Figma و خروجی HTML ارسالی. رابط فارسی و راست‌به‌چپ، واکنش‌گرا، با لوگوی اختصاصی ارسال‌شده.

## فاز ۴ ماه اول: پروفایل و دسترسی حساب

صفحهٔ `#profile` شامل ویرایش نام نمایشی (۱ تا ۸۰ کاراکتر)، معرفی کوتاه اختیاری (حداکثر ۳۰۰ کاراکتر)، نمایش ایمیل فقط‌خواندنی، ذخیره و لغو تغییرات است. اطلاعات نمایشی فقط در حساب صاحب آن نمایش داده می‌شوند. نام جدید در پروفایل و نشست بعدی حفظ می‌شود؛ تغییر ایمیل یا رمز از این فرم ممکن نیست.

مهمان در مراجعه به پروفایل یا طرح‌های حساب سروری به ورود هدایت می‌شود و پس از ورود به مقصد قبلی برمی‌گردد. API پروفایل شناسهٔ حساب را از نشست معتبر می‌گیرد و دسترسی بدون نشست، با نشست منقضی یا پس از خروج را رد می‌کند. دیتابیس حساب‌های قدیمی با افزودن ستون `bio` و بدون حذف داده‌ها به‌روز می‌شود. پیش از ارتقای سرور از دیسک داده نسخهٔ پشتیبان داشته باشید.

در GitHub Pages لینک پروفایل به صفحهٔ ورود و توضیح نیاز به سرور می‌رسد؛ حساب یا ذخیرهٔ پروفایل واقعی شبیه‌سازی نمی‌شود. طرح‌های محلی پیش‌نمایش همچنان از بخش «طرح‌های من» در دسترس‌اند. برای فعال‌شدن حساب واقعی، استقرار Node و تنظیمات سرورِ توضیح‌داده‌شده در ادامه لازم است.

## قابلیت‌های آماده

- صفحهٔ اصلی، سه راهنمای کاربردی و جست‌وجوی پرسش‌های متداول
- استودیوی ساخت چهار پیشنهاد برداری، سه سبک، پنج پالت و انتخاب طرح
- خروجی SVG شفاف و PNG در اندازهٔ ۱۰۲۴×۷۲۰
- ذخیره و بازکردن طرح‌ها؛ در پیش‌نمایش ایستا داخل مرورگر، با سرور داخل حساب
- ثبت‌نام و ورود واقعی با Node.js، SQLite، رمز هش‌شدهٔ scrypt، کوکی HttpOnly، انقضای نشست، محدودیت تلاش ورود و جداسازی طرح‌های کاربران

**تولید این نسخه قالب‌محور است؛ مدل هوش مصنوعی، پرداخت، ایمیل تأیید هنوز متصل نیستند. بازیابی رمز و اعلان ثبت‌نام با تنظیم سرویس ایمیل فعال می‌شوند. توضیح برند فعلاً یادداشت پروژه است. انحصار یا ثبت‌پذیری علامت تجاری تضمین نمی‌شود.**

## اجرای کامل

Node.js 24 یا جدیدتر لازم است. بستهٔ جانبی لازم نیست:

```sh
node server.mjs
```

سپس `http://localhost:3000` را باز کنید. داده‌ها به‌صورت پیش‌فرض در `data/mehrad.sqlite` ذخیره می‌شوند. از این پوشه نسخهٔ پشتیبان تهیه کنید و آن را در گیت ذخیره نکنید.

```sh
node --test api.test.mjs
node --check server.mjs
node --check studio.js
```

## انتشار

### راه‌اندازی سرور روی Render

[آماده‌سازی استقرار مهراد AI روی Render](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Fhesam67mk-coder%2Fmehrad_ai)

تنظیمات `render.yaml` یک وب‌سرویس Docker با پلن Starter و دیسک پایدار ۱ گیگابایتی در `/data` می‌سازد. این ترکیب پولی است؛ مبلغ و شرایط را در صفحهٔ سرویس پیش از تأیید نهایی بررسی کنید. وجود این فایل یا بازکردن لینک بالا به معنی ساخت سرور نیست.

ثبت‌نام، ورود و پروفایل بدون تنظیم سرویس ایمیل اجرا می‌شوند. آدرس خودکار Render از `RENDER_EXTERNAL_URL` خوانده می‌شود و در صورت تعیین `APP_URL`، آدرس دلخواه شما اولویت دارد. پس از استقرار موفق، آدرس واقعی سرویس را باز کنید و ثبت‌نام، تغییر نام، خروج و ورود مجدد را بررسی کنید. `/api/health` باید پاسخ موفق بدهد. GitHub Pages به‌تنهایی هنوز حساب واقعی ندارد؛ آدرس سرویس Render نسخهٔ کامل خواهد بود.

برای فعال‌کردن اعلان ثبت‌نام و بازیابی رمز، بعداً `RESEND_API_KEY` و `MAIL_FROM` را در تنظیمات محرمانهٔ همان سرویس وارد کنید و سرویس را دوباره مستقر کنید. تا آن زمان اعلان‌ها در صف پایدار می‌مانند و بازیابی ایمیلی غیرفعال است. کلیدها را در گیت‌هاب یا چت نفرستید.

### پیش‌نمایش GitHub Pages

فایل‌های `index.html`, `styles.css`, `studio.js`, `logo.js`, `brand.png` و `Vazirmatn.woff2` را از شاخهٔ main و ریشه منتشر کنید. فایل `.nojekyll` نیز موجود است. این نسخه فقط پیش‌نمایش تعاملی با ذخیرهٔ مرورگری است؛ ثبت‌نام واقعی ندارد. فایل‌ها با بازکردن مستقیم `file://` اجرا نمی‌شوند؛ وب‌سرور لازم است.

### نسخهٔ دارای حساب کاربری

Dockerfile و `render.yaml` برای استقرار آماده‌اند. Render Blueprint شامل پلن پولی و دیسک پایدار است؛ هزینه را پیش از تأیید بررسی کنید. صرف قرارگرفتن کد در GitHub سرویس را مستقر نمی‌کند. یا روی سرور دارای Node.js 24 اجرا کنید:

```sh
NODE_ENV=production HOST=0.0.0.0 PORT=3000 DATA_DIR=/data node server.mjs
```

نسخهٔ عملیاتی به HTTPS و یک دیسک پایدار برای SQLite نیاز دارد. `NODE_ENV=production` کوکی Secure را فعال می‌کند؛ در محیط توسعهٔ HTTP آن را تنظیم نکنید. مسیر `/api/health` برای health check موجود است. این معماری یک نمونهٔ سرور دارد و برای چند replica یا فایل‌سیستم موقت serverless مناسب نیست. پیش از عرضهٔ تجاری، تأیید ایمیل، حذف حساب، راه ارتباطی پشتیبانی و نسخهٔ پشتیبان پایگاه داده را اضافه کنید.

## فایل‌های طراحی

`design-reference.html` خروجی اصلی طرح به‌صورت خودکفا است و برای مراجعه نگه‌داری شده؛ رابط کاربردی جدید در ریشه قرار دارد. `brand.png` لوگوی ارسالی است. قلم Vazirmatn با مجوز SIL Open Font License به‌صورت محلی عرضه شده؛ مجوز در `OFL.txt` قرار دارد.

SVG متن قابل ویرایش دارد و نمایش متن به قلم سیستم مقصد وابسته است. PNG خروجی تصویری است. اطلاعات کاربران، کلید سرویس‌ها یا داده‌های واقعی را در مخزن عمومی قرار ندهید.

## فاز ۳ ماه اول: حساب کاربری و ایمیل

ثبت‌نام، ورود، خروج و بازیابی رمز پیاده‌سازی شده‌اند. نام، ایمیل و زمان ثبت‌نام برای `hesam67mk@gmail.com` ارسال می‌شود؛ رمز عبور، توکن نشست و لینک بازیابی در اعلان مدیر قرار نمی‌گیرند. فرم ثبت‌نام این موضوع را به کاربر اطلاع می‌دهد. هنوز تأیید مالکیت ایمیل انجام نمی‌شود؛ اطلاعات اعلان، ادعای کاربر است.

برای ارسال واقعی، در تنظیمات محرمانهٔ میزبان سه متغیر را تنظیم کنید (نمونه در `.env.example`):

- `APP_URL`: آدرس HTTPS نسخهٔ دارای سرور، برای ساخت لینک بازیابی؛ آدرس GitHub Pages نباشد.
- `RESEND_API_KEY`: کلید سرویس Resend؛ فقط روی سرور.
- `MAIL_FROM`: فرستندهٔ تأییدشده در سرویس ایمیل، مانند `Mehrad AI <accounts@your-domain.example>`.

فایل محیطی با اجرای `node --env-file=.env server.mjs` خوانده می‌شود. فایل واقعی .env و کلیدها را منتشر نکنید. Gmail بالا گیرنده است و به رمز آن نیاز نیست. پس از تنظیم، یک ثبت‌نام واقعی انجام دهید و رسیدن اعلان به صندوق ورودی را بررسی کنید. تا تنظیم و تست سرویس، تحویل ایمیل تأیید نشده است.

اعلان‌های ثبت‌نام در صف SQLite پایدار می‌مانند و هنگام آماده‌شدن سرویس ارسال می‌شوند. خطاهای موقت با فاصلهٔ افزایشی دوباره امتحان می‌شوند؛ صف را در پشتیبان داده‌ها نگه دارید. بازیابی رمز لینک ۳۰دقیقه‌ای یک‌بارمصرف دارد، توکن در پایگاه داده هش می‌شود، پاسخ ایمیل ناشناس و شناخته‌شده یکسان است، و تغییر رمز همهٔ نشست‌های قبلی را باطل می‌کند. خطای ارسال بازیابی لینک را باطل می‌کند؛ کاربر باید دوباره درخواست کند.

GitHub Pages فقط رابط را نمایش می‌دهد و اجرای Node/SQLite/ارسال ایمیل در آن فعال نیست. برای حساب‌های واقعی باید همین برنامه روی میزبان Node.js 24 با HTTPS و دیسک پایدار اجرا شود. تست‌های ایمیل از یک گیرندهٔ محلی ساختگی استفاده می‌کنند و هیچ ایمیل واقعی نمی‌فرستند.
